# Release commands and evidence

`npm run release:checks` runs conflict detection, a fresh nonincremental type check, lint, full regression tests, dependency audit (high and critical block), strict readiness, strict static content, fixture export/import and hardening. It continues collecting after a failed command. Exit zero means only those source checks passed; the report still says NO-GO because no release candidate was tested. `CI_FUZZ_WEEKS=50` is the smaller PR sample; default local/Windows hardening is 500. Neither proves season balance.

`npm run release:verify` adds the production web build/compiled worker check, shipping layout and missing release evidence. It intentionally fails without a fresh Windows package. `npm run release:verify -- --package` builds the Windows package through the existing App ID preflight and dist builder, checks shipping layout, hashes all unpacked artifact bytes, and associates them with the source/lock identity. It never uploads to Steam. Packaging may normalize images; a source change during any run fails source identity and requires review and a new run. Stop a local Next server before running a command that rebuilds its `.next` directory.

Reports and individual logs are in unique `tmp/launch-evidence/run-*` directories, written after every gate. Source identity includes tracked and nonignored untracked files and their hashes, including dirty edits; generated evidence is excluded. Ignored files are not covered, which is why this is not a complete build supply-chain attestation. A previous dist folder cannot satisfy the same-run package gate. An artifact hash proves identity, not that Windows installation, Steam or save recovery passed.

Launch packages besides L34 and the final L36 owner review must have verified status (or explicit exclusion for conditional scope) before candidate checks can pass. L34 and L36 are excluded from that status check to avoid a self-reference, but its upstream L02/L06/L07 packages are required. GO/NO-GO remains L36 owner review. Partial acceptance, missing gates, duplicate gate records, nonzero exit, process errors and source changes are failures. Static findings cannot approve rights or player acceptance.

All public assets are now in the filename/signature scan. Inline art, provenance, packaged notices and actual inclusion still need L08 review; no static scan claims that coverage. Historical bulk medium baselines are retained for history but ignored as acceptance. Bulk baseline rewriting is disabled. No findings have been waived in this pass; reviewed, item-specific, expiring exceptions remain future work if needed.

CI uses the same source runner, no longer ignores lint errors, retains evidence on failed jobs, separately builds the web app, and provides manual Windows candidate packaging with no publishing credentials. CI execution is not verified until a remote run occurs; this task does not push or dispatch workflows.
