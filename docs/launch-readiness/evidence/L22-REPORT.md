# L22 - Onboarding and the first session

Reviewed 14 September 2026. **Partial. Implementation, regression tests and programmatic Windows runtime checks pass. UI interaction and fresh-player acceptance remain open.** Dependencies L16, L17 and L21 retain unresolved validation/calibration work.

## Changes

- Replaced the nine-slide opening overlay with a contextual, nonmodal first-session guide. Home shows one next action; squad, finance, report and other management pages show the same guide above their content. It does not cover controls or wait for exit animations. Match play, tactics/veto, setup, Map Studio and development routes suppress the contextual guide. Ended and loading careers suppress it too.
- Four steps now cover squad assessment, finances, a deliberate weekly plan and review of an actual own-team result. Squad/finance steps require an explicit Reviewed action on the relevant page; following a link cannot complete anything. Selecting a valid affordable weekly activity records the plan step. Regular training is visible and selectable even before another plan has been picked and remains available in debt. Opponent-only results do not satisfy the match step. Recruitment, schedule/next fixture and result follow-up remain reachable depending on roster/result state.
- New optional `firstSession` data belongs to the career and passes through the canonical SaveManager/create/snapshot/load paths. Skip persists dismissal; replay resets guide progress only and preserves club cash, players, contracts, dates, results and the new-game preference. Completing all steps removes introductory content. Old or unsupported guide data defaults to dismissed instead of inheriting another career's progress; Settings can replay it. The old device-global checklist key is no longer read.
- The selected weekly focus was absent from canonical saves. Added optional `selectedWeeklyActivity`, explicit default/reset on new and loaded careers, and enum validation on load. Selecting a plan and guide review/skip/replay request the existing serialized career save pipeline; they do not advance time. Paid plans reject insufficient current cash at the store boundary and show a disabled explanation in the widget. Costs are still settled by the existing weekly processor, not charged when selecting.
- Setup now keeps a bounded device-local draft of the manager name, selected club, sandbox choice and custom team details. Reload restores custom inputs at the first validation step. Drafts are separate from career/map storage, survive failed creation, and clear after successful creation. Invalid fields, unsupported versions and oversized logo data are filtered; custom logo data above 500 KB is not retained and the UI says it must be selected again after reload. Storage failure shows an honest message instead of interrupting setup.
- Existing-club creation rechecks the manager name and current club unlock state at Start, including switching sandbox off after selecting a locked club. It checks store creation errors before recording a new campaign or navigating. Ref guards cover repeated start/create clicks. Local data failures offer a retry and retain the draft. Sandbox copy clarifies that it unlocks club selection rather than reducing match difficulty.
- Custom club creation opens the roster builder directly after successful saving; removed the forced 3.5-second celebration and its timer/confetti code. Review copy explains the empty roster and five-player requirement. Difficulty help distinguishes recurring sponsor/merchandise income from separately handled prizes. Recurring training suggestions allow leaving sessions unused; help no longer claims a specific chemistry win effect or a win-streak money bonus.

Changed source files and hashes are in [build identity](L22-build-identity.json).

## Compatibility and rollback

The two new career fields are optional; no destructive migration or save-version bump is needed. New careers initialize guide state according to the new-game tutorial preference. Old careers load with the guide dismissed and no pending weekly focus unless a supported saved value exists. The obsolete global checklist remains untouched but no longer controls careers. Draft storage uses its own versioned key and whitelisted bounded fields; clearing that draft cannot clear a career or map draft.

New guide and plan changes use the existing save queue. Save failures continue through the normal save-error handling; a passing in-memory interaction does not prove a durable write. Older executables can ignore the optional fields but may lose them when re-saving and may again lose pending weekly focus. Use a separate recovery copy with a matching older build for rollback; do not overwrite owner careers or drawings.
