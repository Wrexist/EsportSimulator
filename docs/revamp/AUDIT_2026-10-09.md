# Revamp Audit — 2026-10-09

Five parallel audits: match engine, radar/live match, visual design, game loop, runtime health.
Scratch scripts and raw output: `tmp/audit-2026-10-09/{sim,radar,runtime}/` (not committed).
No source files were changed by the audit.

---

## 1. The one-sentence verdict

**The game decides each round with a weighted coin flip, then invents kills, positions and stats to fit — so the radar, the player attributes, the tactics and the stats all *feel* fake because they *are* fake.** On top of that sits a generic "navy glass SaaS dashboard" UI and ~22 menu destinations, many shallow or broken.

The fix is not polish. It is one new core (a **round-script engine**) that every visible system reads from, plus a focused UI and loop built around it.

## 3. Findings by area (top items only)

### 3a. Match engine — "not realistic"
Measured over ~4,500 simulated maps (`tmp/audit-2026-10-09/sim/run-*.ts`).

| Metric | Ours | Pro CS2 | |
|---|---|---|---|
| Loser scores ≤3 | **28.5%** | 6–10% | 3–4× too many blowouts |
| Overtime | 5.6% | 8–12% | too low |
| Win next round after a win | **76%** | 60–65% | streak/momentum snowball |
| 1vX clutches won | **0** in 1,200+ maps | ~2/map | impossible (cap at 3 winner deaths) |
| Trade kills | **0%** | 20–25% | bug: `lastDeath` overwritten |
| Kills/round · ADR · rating | 5.2 · 48 · 0.86 | ~7.1 · ~76 · 1.00 | all deflated |
| Force-buy vs full-buy win% | 11% (= eco) | 25–30% | 10% floor clamp |
| AI grenades bought | **0** | 3–4/player | missing |
| Bomb explodes at plant+40s | 63% | 100% | timeline bugs |

- **P0** AI-vs-AI path multiplies staff bonus ×10 with no cap — level-5 coach = **+40 pts** map-win% (`engine/match-engine.ts:182-186`, `engine/match/team-strength.ts:90`, `engine/tournament-manager.ts:65-68`).
- **P0** Fixed playoff seeds → same matchup gives same winner across seasons **100%** of the time (`engine/tournament-manager.ts:1133-1147`, `double-elim-handlers.ts`, `legacy-series.ts:313`).
- **P1** Dead attributes: AWP, rifle, pistol, eyesight, entry, creativity, leader, clutch → **0.0 effect**. Higher reaction makes you die more (`round-outcome.ts:115`). Roles only count as "distinct labels" (`team-strength.ts:71`).
- **P2** Map veto barely matters (0.15 pts/round); one tactic stat worth +23.

### 3b. Radar / live match — "broken and very bad"
Measured over 200 rounds × 8 maps (`tmp/audit-2026-10-09/radar/`).

- **P0** Killer is the victim's nearest enemy in only **29%** of kills (≈ random).
- **P0** Bomb site is a coin flip in **100%** of rounds (PLANT events carry no site).
- **P0** Teams move as blobs: median teammate distance 2.1% of map; 39% of teammate pairs overlap.
- **P0** Half of kills draw no shooter line; death X vanishes after 4 s.
- **P1** SKIP RND sets speed 100× and never resets it (`hooks/useLiveMatch.ts:738,744`).
- **P1** Radar capped at 520 px inside the normal app shell; sidebar of 20 locked items + "Play match" button still visible during the match.
- **P1** Positions re-simulated from t=0 twice per tick on the main thread (p95 45 ms/tick) — bad under the software-rendering default.
- **P1** Walk mask is a PNG brightness threshold, not the nav mesh (Nuke lower 75% false-walkable); Vertigo floors inverted.
- **P2** No utility (`smokes = []` always), no HP, no bomb carrier, no weapon icons, no scrubber. Raw Valve `_psd` overviews washed out with a CSS filter (also a content-clearance risk).
- Four radar implementations exist; only the "estimated 2D" one is live. `MapRadar3D.tsx` (469 lines + three.js deps) is imported nowhere.

### 3c. Visual design — "feels cheap"
- **No type identity:** body font is Segoe UI fallback; Archivo Black is loaded but `font-display` used 0×; Inter features enabled but Inter never loaded.
- **Three token systems fighting:** `src/design/tokens.ts` (7 uses), shadcn `--primary` = white, `app/premium-ui.css` reskins everything with `!important`.
- **Tiny uppercase text:** 677× 10px, 196× 9px, 114× 8px, 994 `uppercase`.
- **Component sprawl:** 5 panel classes, 392 ad-hoc `bg-white/N` combos, 23 different `<h1>` styles, 5 team-logo and 6 portrait components, 355 hard-coded hex colours.
- **Colour has no meaning:** every stat traffic-lit (a rifler's "AWP 0" in red); AWPer role = red, Support = green.
- **No moments:** all sound is Web Audio oscillator beeps, music defaults to 0, trophy win is a small glass modal, no match intro; tutorial checklist overlaps "DEFEATED".

### 3d. Game loop — "not fun"
- Numbers on screen mostly don't decide matches (strength reads only `p.skill`, `team-strength.ts:57`).
- **Equipment = +56% strength for ~$40k; AI clubs own none** (`engine/equipment-manager.ts:291`, `engine/data-generator.ts:368`). $500k start vs ~$3.3k/week costs → no money pressure.
- Best tactical levers (counter-playstyle, anti-strat, VOD) **locked for the first match** (Tactical Center level 0).
- Dead days: `advanceDay` only moves the date; 6 empty "Next day" clicks per week.
- Live match ≈ 25 min/map replaying a result that was already rolled.
- Broken/fake: staff meetings can't be booked (`duration: 0` vs store min 1), bootcamp/marketing never charged, legend coach wage never paid, team-wide morale choices no-op, "Hype +10" labels promise nothing.
- Sprawl: training split across 5 places; same building has 3 names; FPL ≈ 0 impact; Map Studio author notes reachable from Settings.
- First impression: only 41/198 clubs open at level 1; sacking dead-ends to "Load Save".

### 3e. Runtime health
Type-check, 2,051 tests and lint are green; all 46 routes render and a full match plays end to end. The real runtime problems are a phantom career from the top bar, a "Skip match" that doesn't skip, slow max speed, low FPS under software rendering, and saves that start at ~5 MB. Details in section 6.

### Recommended order
`0 → 1 (Squad vertical slice first) → 2 → 3 → 4 → 5`. Phase 2 and Phase 1 can run in parallel (engine vs UI). Phase 3 depends on Phase 2.

### Engine migration path (resolves the one disagreement between audits)
The radar audit proposes keeping today's outcome resolver and adding a script builder that places duels consistent with it. The engine audit proposes letting the script decide outcomes. Do both, in order:

1. **2A — Script on top of the existing resolver** (~120 h): callout graphs baked from `public/map-studio/spatial/*.json`, events gain `site` / `plan` / `location`, script builder places each kill in line of sight, utility throws, bomb carrier. Fixes the radar without changing results or saves.
2. **2B — Script decides outcomes** (~120–160 h): duels resolved from aim, weapon, peek/hold, utility, trades; streak/momentum bonuses removed; calibration harness gates every change against the pro-CS2 table in §3a.

The physical 64 Hz engine (`engine/spatial`) stays lab-only: ~65 CPU-s per round and failed calibration (`docs/PHYSICAL-CAREER-RADAR.md`).
